# Foval Learning Institute: Curriculum Map

This is the master map of what Foval Learning Institute teaches. It is organised as **schools → courses**. Every course folder under `courses/` must belong to exactly one school listed here, using the school's slug as its parent folder.

The map is deliberately ambitious. Most courses are `planned`. The point of writing the whole map now is so that every course we build knows where it sits, what comes before it, and what it feeds into. All 174 of them are placed on the Foval Core, in the order they should be taken.

**Design principles**

1. **Two halves, one person.** Half the map is what a serious classical university teaches (history, philosophy, mathematics, science, literature). The other half is what almost no university teaches but every capable adult needs (money, sales, health, self-reliance, using AI). A Foval graduate should be both well-read and street-smart.
2. **Foundations first, and everything in an order.** The School of Foundations teaches how to think, read, and evaluate evidence, and everything else assumes it. More broadly, every course on the map carries a place in the Foval Core, so a learner is never left guessing what a course comes after.
3. **Neutral ground, honestly labelled.** On contested questions the neutral schools teach the debate, not a side. One school, Christian Studies, teaches from a declared standpoint and says so on every course. See `docs/EDITORIAL_STANDARDS.md` Part 3.
4. **Depth over breadth per course.** A course should leave you genuinely competent in its subject, not "exposed" to it.

**Levels:** `Foundation` (no prerequisites), `Core` (assumes Foundation courses), `Advanced` (assumes Core).
**Status:** `planned` → `research` → `drafting` → `published`. A course is published when its lessons have been through the review pipeline; it keeps improving through the feedback loop after that. One of the original starter courses, Writing Clearly, is marked `published` but still owes its Stage 4 and voice pass; Algebra Essentials was rebuilt on 2026-09-09 and owes its voice pass. See `docs/QUEUE.md`.

**Path:** every course sits in a term of the Foval Core. There is no elective tier; see "Placing a course on the Core" at the foot of this file.

## Adding to the map

To propose a new course, add a row to the right school with status `planned`, a level, a one-line
note, and a **Path** cell naming the term it sits in. Create the course folder only when research
begins (`/research-course`). Keep the map as the single source of truth for what exists and what is
intended.

## Placing a course on the Core

Every course on this map sits somewhere on the Foval Core. **There is no elective tier.** That
changed on 2026-09-08, on John's call, and the reason is worth keeping: the map had 122 courses
marked `elective`, which meant 122 courses with no ordering at all. A learner who wanted Data
Analysis or Project Management had no way to know what came before it. The tradeoff was made with
open eyes: the Core is no longer a two-year general-education spine, it is the whole curriculum in
order, and a learner takes as much of it as they want.

So the **Path** cell holds a term, `T1` upward, and nothing else. The course must also appear in
that term in `curriculum/core-path.yaml`, in the position where it should be taken. That file sets
the order; this column records the decision. `npm run validate` fails if a row has a blank or
unrecognised Path cell, if the two files disagree about which term a course sits in, or if a course
on the path has no row here. A new course cannot reach the map without someone deciding when it
should be taken, and the decision cannot quietly rot afterwards.

**Choosing the term.** Work down this list and stop at the first answer:

1. **What does it need first?** A course goes in the term after the last one it depends on. This is
   the rule that does most of the work: Calculus after Algebra, Data Analysis after Python,
   Biology II after Biology I, Macroeconomics after Micro, the Christian tradition in depth after
   Scripture. If it depends on nothing, it can go early.
2. **How soon is it useful?** Among courses with no prerequisites, the ones a learner will use this
   month come first. That is why Cooking Fundamentals and Time Management sit in the first three
   terms and Architecture sits in the fifteenth. A course nobody needs urgently and nothing depends
   on goes late.
3. **Which term's theme does it belong to?** Each term has a theme, stated in `core-path.yaml`.
   A course that fits no theme is usually a sign that a term is missing, not that the course is
   wrong.
4. **Does the term still balance?** Terms are seven courses and mix at least two schools, so a
   learner following the path is always working across head, world, and hands. If adding a course
   makes a term eight, something moves.
5. **Where in the term?** Order inside a term is the order courses should be taken. Put it after
   whatever it leans on.

**When a course moves**, change both files in the same commit and run `npm run validate`. The
numbered term list above is generated from `core-path.yaml` by `npm run path -- --write`; never edit
it by hand.

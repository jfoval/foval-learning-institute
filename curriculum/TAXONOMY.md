# Foval Learning Institute: Curriculum Map

This is the master map of what Foval Learning Institute teaches. It is organised as **schools → courses**. Every course folder under `courses/` must belong to exactly one school listed here, using the school's slug as its parent folder.

The map is deliberately ambitious. Most courses are `planned`. The point of writing the whole map now is so that every course we build knows where it sits, what comes before it, and what it feeds into.

**Design principles**

1. **Two halves, one person.** Half the map is what a serious classical university teaches (history, philosophy, mathematics, science, literature). The other half is what almost no university teaches but every capable adult needs (money, sales, health, self-reliance, using AI). A Foval graduate should be both well-read and street-smart.
2. **Foundations first.** The School of Foundations teaches how to think, read, and evaluate evidence. Everything else assumes it.
3. **Neutral ground, honestly labelled.** On contested questions the neutral schools teach the debate, not a side. One school, Christian Studies, teaches from a declared standpoint and says so on every course. See `docs/EDITORIAL_STANDARDS.md` Part 3.
4. **Depth over breadth per course.** A course should leave you genuinely competent in its subject, not "exposed" to it.

**Levels:** `Foundation` (no prerequisites), `Core` (assumes Foundation courses), `Advanced` (assumes Core).
**Status:** `planned` → `research` → `drafting` → `published`. A course is published when its lessons have been through the review pipeline; it keeps improving through the feedback loop after that. The four original starter courses are marked `published` but were written before the pipeline existed and are queued to go through it.

## Adding to the map

To propose a new course, add a row to the right school with status `planned`, a level, a one-line
note, and a **Path** cell. Create the course folder only when research begins (`/research-course`).
Keep the map as the single source of truth for what exists and what is intended.

## Placing a course on the Core

Every course on this map carries a placement decision in its **Path** column. There are two possible
values and no third option:

- **`T1` to `T8`**: the course belongs on the Foval Core, in that term. It must also appear in that
  term in `curriculum/core-path.yaml`, in the position where it should be taken. That file sets the
  order; this column records the decision.
- **`elective`**: the course is worth teaching but does not belong on the general-education spine.
  It must not appear in `core-path.yaml`.

`npm run validate` fails if a row has a blank or unrecognised Path cell, if the two files disagree
about which term a course sits in, or if a course on the path has no row here. So a new course
cannot reach the map without someone deciding where it sits, and the decision cannot quietly rot
afterwards.

**Choosing the term.** Work down this list and stop at the first answer:

1. **Does the Core need it?** The Core is what a broadly educated adult should know, not everything
   worth knowing. A course that serves a career, a craft, or a particular interest is an elective,
   however good it is. Graphic Design Fundamentals and Technology Leadership are electives for this
   reason; Statistics for Citizens is on the Core because nobody can read the news without it.
2. **What does it need first?** A course goes in the term after the last one it depends on. If it
   depends on nothing, it can go early.
3. **Which term's theme does it belong to?** Each term has a theme, stated in `core-path.yaml`.
   A course that does not fit any of them is probably an elective.
4. **Does the term still balance?** Every term mixes at least two schools and stays roughly the size
   of its neighbours. If adding a course makes a term much longer than the rest, something else in
   that term moves out or the course waits for a later one.
5. **Where in the term?** Order inside a term is the order courses should be taken. Put it after
   whatever it leans on.

Adding a course to the Core is a change to what the institute claims an educated person needs, so it
is a decision worth making slowly. Marking a course `elective` costs nothing and can be revisited.

**When a course moves**, change both files in the same commit and run `npm run validate`. The
numbered term list above is generated from `core-path.yaml` by `npm run path -- --write`; never edit
it by hand.
